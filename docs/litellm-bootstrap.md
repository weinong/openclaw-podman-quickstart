# Bootstrap LiteLLM sidecar for OpenClaw

This guide runs LiteLLM as a sidecar in the same rootless Podman pod as OpenClaw and preconfigures OpenClaw to use it as the default model provider.

## Target architecture

```text
Podman pod: openclaw
├── openclaw-gateway
│   └── uses LITELLM_API_KEY from ~/.config/openclaw-gateway/gateway.env
├── openclaw-litellm
│   └── listens on http://127.0.0.1:4000 inside the pod
└── openclaw-browser
    └── persistent CDP endpoint on http://127.0.0.1:9222
```

The pod publishes LiteLLM on host loopback only:

```text
127.0.0.1:4000:4000
```

## Files installed

The installer copies:

```text
~openclaw/.config/containers/systemd/litellm.container
~openclaw/.config/litellm/config.yaml
~openclaw/.config/litellm/litellm.env
```

It also updates:

```text
~openclaw/.config/openclaw-gateway/gateway.env
~openclaw/.openclaw/openclaw.json
```

## Configure provider credentials

The default LiteLLM config in this repo routes to OpenAI models and expects `OPENAI_API_KEY`.

After running the installer, edit:

```bash
sudo -iu openclaw
chmod 600 ~/.config/litellm/litellm.env
nano ~/.config/litellm/litellm.env
```

Set:

```bash
OPENAI_API_KEY=sk-...
```

Alternatively, use the helper from the repo checkout:

```bash
OPENAI_API_KEY='sk-...' sudo -E bash ./scripts/configure-litellm.sh openclaw
```

The helper writes:

```text
~openclaw/.config/litellm/litellm.env
```

with mode `0600`, and also writes `LITELLM_API_KEY` into:

```text
~openclaw/.config/openclaw-gateway/gateway.env
```

OpenClaw uses `LITELLM_API_KEY` to authenticate to LiteLLM. The default value is the local LiteLLM master key generated by the installer.

## Default LiteLLM models

The repo's default `config/litellm/config.yaml` exposes these model names:

```text
openai/gpt-4.1
openai/gpt-4.1-mini
openai/gpt-4o-mini
```

OpenClaw is preconfigured to use:

```text
litellm/openai/gpt-4.1-mini
```

as the default primary model.

## OpenClaw config

The installer patches this provider block into `~openclaw/.openclaw/openclaw.json`:

```json
{
  "models": {
    "providers": {
      "litellm": {
        "baseUrl": "http://127.0.0.1:4000",
        "apiKey": "${LITELLM_API_KEY}",
        "api": "openai-completions",
        "models": [
          {
            "id": "openai/gpt-4.1-mini",
            "name": "GPT-4.1 mini via LiteLLM",
            "reasoning": false,
            "input": ["text", "image"],
            "contextWindow": 1047576,
            "maxTokens": 32768
          }
        ]
      }
    }
  },
  "agents": {
    "defaults": {
      "model": {
        "primary": "litellm/openai/gpt-4.1-mini"
      }
    }
  }
}
```

The actual file includes both `openai/gpt-4.1` and `openai/gpt-4.1-mini` entries.

## Start or restart LiteLLM

As the service user:

```bash
sudo -iu openclaw
systemctl --user daemon-reload
systemctl --user restart litellm.service
```

Check logs:

```bash
journalctl --user -u litellm.service -f
```

## Validate LiteLLM

As the service user:

```bash
sudo -iu openclaw
set -a
source ~/.config/litellm/litellm.env
set +a

curl -fsS http://127.0.0.1:4000/health/liveliness | jq .

curl -fsS http://127.0.0.1:4000/models \
  -H "Authorization: Bearer ${LITELLM_MASTER_KEY}" | jq .
```

You can also run:

```bash
./openclaw-podman-quickstart/scripts/doctor-openclaw-podman.sh
```

## Restart OpenClaw gateway

After changing LiteLLM keys or config:

```bash
sudo -iu openclaw
systemctl --user restart litellm.service
systemctl --user restart openclaw-gateway.service
```

## Switching to another provider

Edit:

```text
~openclaw/.config/litellm/config.yaml
~openclaw/.config/litellm/litellm.env
```

For example, replace `OPENAI_API_KEY` with `ANTHROPIC_API_KEY` and change `model_list` entries to Anthropic model names. Then update the OpenClaw model IDs in `~openclaw/.openclaw/openclaw.json` so they match LiteLLM's exposed `model_name` values.

## Security notes

- Do not commit `~openclaw/.config/litellm/litellm.env`.
- Do not expose port `4000` beyond host loopback unless you have explicit authentication, TLS, and network policy.
- Prefer LiteLLM virtual keys with budgets for long-lived OpenClaw deployments.
